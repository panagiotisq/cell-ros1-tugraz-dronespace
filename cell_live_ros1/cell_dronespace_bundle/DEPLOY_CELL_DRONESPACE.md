# CELL — Drone-Space Live Deployment (ROS 1)

This bundle contains everything needed to run **CELL** (map-relative event-camera
localization) live against the aligned mocap-world map, and it is the authoritative spec for
how the drone-space (tugraz) sequences were trained. Read it before wiring ROS.

---

## 0. TL;DR — the key decisions

| Thing | Value |
|---|---|
| Event representation | **2-channel** per-polarity **latest-timestamp time surface**, **50 ms** window, **half-res 640×360**, exp-decay to [0,1]. NOT 1-channel, NOT STC/Trail. |
| Crop (h,w,x,y) | **(288, 512, 36, 64)** |
| Calibration | **half-res intrinsics** (full-res / 2) |
| max_depth | **10.0 m** (indoor z-ceiling) |
| Depth input channel | **ch1 = partial_light completion** (`di[:,1:2]`), not sparse ch0 |
| Backbone | `"edge"` → `Backbone_Edge_FF` (flow + edge + confidence head) |
| Inference iters | **24** (drop to 12 for frame-rate; safe — conf snapshots are absolute-indexed) |
| Correspondence selection | **floor0** probabilistic (`sel_pweight(conf, 0.0)`) |
| Checkpoint | `checkpoint/best_model.pth` (seq3 edge, decoupled-β1.5, partial_light, half-pert) |
| Map | `fused_clean_mocap.ply` (mocap-world frame) |
| Pose guess (live) | **Mode A: mocap-seeded.** **Mode B: self-track + mocap recovery.** Never pure self-track — it diverges. |

cd code/core/correlation_package && python setup.py build_ext --inplace && cd -
#   -> produces visibility*.so and correlation*.so importable from core/

Sanity check: `python -c "import torch,visibility,correlation,mathutils,poselib; print('ok')"`.
Launch with `LD_LIBRARY_PATH=$CONDA_PREFIX/lib` (so torch picks up the env's libs) and
`PYTHONUNBUFFERED=1` for live logging.

## 4. THE EVENT REPRESENTATION (authoritative — matches the trained model)

The model input is a **2-channel, 50 ms, per-polarity latest-timestamp time surface at
half-res** — not STC/Trail, not a 1-channel surface, and not linear normalization (the M3ED
pipeline's own `code/tools/m3ed/event2frame.py`, if you find it, uses linear age/window — a
different pipeline, not this checkpoint's).

Verified empirically on the real training frames (generated by
`drone_space/scripts/gen_tugraz.py`): the minimum nonzero value is
**0.03568 = exp(-0.050/0.015) exactly**, a hard floor with zero values below it — an
**exponential decay**, not linear. The encoder is `BasicEncoder(input_dim=2)` → **exactly 2
channels**. A real frame (`event_frames_ours_50ms_half/left/event_frame_00000.npy`) is shape
**(360, 640, 2)**, float32, values in **[0.03568, 1.0]** for nonzero pixels, 0 for empty.

### Exact spec to reproduce live from the event stream
Per inference tick, over the **last 50 ms** of events (`WIN = 0.050`):
1. Split events by **polarity** → channel 0 = one polarity, channel 1 = the other.
2. Per pixel, keep the **timestamp of the most recent event** in that channel (a latest-
   timestamp *time surface* — not a count, not an IWE).
3. `value = exp(-(t_end - t_event) / TAU)`, `TAU = 0.015` (15 ms); empty pixels = 0.
4. **Half resolution:** native 1280×720 → **640×360** (factor-2 downsample), so the stored
   array is `(H=360, W=640, C=2)`.

STC/Trail denoising is **not** applied (the training frames were made without it; adding it
live would be a train/test mismatch). Reference generator: `gen_tugraz.py` (see
`drone_space/DATASET.md`). Live implementation: `cell_live/event_repr.py` `build_frame()`,
`mode="exp"` (default); a `mode="linear"` path exists (selectable via `--event-repr-mode linear`)
but does **not** match `best_model.pth`.

## 5. GEOMETRY / MODEL CONFIG

Every tugraz sequence is class **indoor** (`core/scene_config.py`):

```
crop (h, w, x, y) = (288, 512, 36, 64)     # center crop of the 360x640 frame
calib_div         = 2.0                     # feed HALF-RES intrinsics (full-res / 2)
max_depth         = 10.0                    # metres; MAX_DEPTH in push_fuse / get_corr
native frame_hw   = (360, 640)
backbone          = "edge"  -> Backbone_Edge_FF
inference iters   = 24
depth input       = ch1 (partial_light completion), i.e. di[:, 1:2]
```

**Calibration:** the event frame is half-res, so feed **half-res** intrinsics. If
`intrinsics.json` is full-res (1280×720), divide fx, fy, cx, cy by 2. The crop offset (x=36,
y=64) is applied internally by `push_fuse`/`get_corr` (it shifts the principal point into the
cropped frame) — don't pre-apply it.

## 6. THE LIVE INFERENCE RECIPE (single frame)

CELL is **map-relative**: it refines a coarse guess pose against the map. It does NOT produce a
pose from nothing. One frame:

```python
# inputs this tick:
#   H_guess : 4x4 world->CAMERA guess pose (float64)   -- see §7 for where it comes from
#   ev      : event frame tensor (1, 2, 360, 640), float32 in [0,1]
#   pc      : the map points in WORLD (mocap) frame, (N,3) or (N,4) homogeneous
#   calib   : [fx, fy, cx, cy]  HALF-RES

# 1) express the perturbation as the guess pose itself (world-map formulation):
#    feeding pc in WORLD frame with RT = H_guess makes push_fuse render the map
#    exactly as seen from the guess camera (pc_rotated = H_guess @ X_world). NO GT used.
RT    = ortho(H_guess)                         # world->cam guess
R_err = quaternion_from_matrix(torch.tensor(RT)).float()   # (w,x,y,z)
T_err = torch.tensor(RT[:3, 3]).float()

# 2) build the network inputs (depth rendered from the guess + the event image):
dp = Data_preprocess(calib.unsqueeze(0), 3, 5, partial_fill="partial_light")
ei, di, _, _ = dp.push_fuse(ev, [pc], T_err.unsqueeze(0), R_err.unsqueeze(0), dev,
                            MAX_DEPTH=10.0, split="test", h=288, w=512)
di = di[:, 1:2, :, :]                          # partial_light completion = CELL depth input

# 3) forward pass -> flow + per-correspondence confidence:
_, flow_up, depth2edge, cf = model(di, ei, iters=24, test_mode=True, output_conf=True)
cm = F.softplus(cf)[0, 0].cpu().numpy()

# 4) correspondences -> confidence selection (floor0) -> weightless PnP:
p2, p3, idxc, cp = EF.get_corr(flow_up, di, calib.unsqueeze(0))
conf = cm[idxc[:,0].astype(int), idxc[:,1].astype(int)]
sel  = EF.sel_pweight(conf, 0.0, rng)          # floor0 (deployed default)
o    = EF.solve(p2[sel], p3[sel], cp)          # poselib PnP -> RT_pred (quat, transl)

# 5) update the absolute pose:
RT_pred = mat_from_qt(o[0], o[1])
H_est   = ortho(np.linalg.inv(RT_pred) @ H_guess)   # corrected world->cam
```

The helpers (`ortho`, `mat_from_qt`, `centre`, constant-velocity prediction) are in
`tools/tracking/track_cell.py`. The offline tracker uses per-frame cam-frame map crops
(`pc_k = G_k @ X_world`, `RT = H_guess @ inv(G_k)`); the live loop uses the world-map
formulation above (pc in world, `RT = H_guess`) — algebraically identical, and it uses **no
ground truth**.

**Speed:** crop the map (~1.2 M points) to the guess camera frustum before `push_fuse` (points
in front of the camera, within max_depth and the FoV). Expect ~120–230 ms/frame at iters=24 on
an 11 GB GPU; iters=12 roughly halves the flow cost.

**Health signals per frame (for Mode B recovery, §7):** PnP inlier count (`len(sel)` and the
poselib inlier set) and the step magnitude `||centre(H_est) − centre(H_guess)||`. A tiny inlier
count or a large step = bad frame.

## 7. WHERE THE GUESS COMES FROM

CELL refines a guess inside a **±5° / 0.5 m basin**; the guess source each frame is the one
real design choice. Pure self-tracking is **not deployable** — measured GT-free free-running on
seq3: position-init drifts (median APE ~154 cm, 42% of frames lost) and velocity-init
dead-reckons into runaway. Use mocap as the guess, or as a recovery anchor:

**Mode A — mocap-seeded.** Each frame, `H_guess` = the live mocap pose (world→body from mocap,
composed with `T_body_camera` → world→cam). CELL refines it against the map. Guaranteed inside
the basin and smooth; proves the whole event→time-surface→CELL→PnP→pose stack end-to-end and
shows CELL agreeing with mocap live. Start here.

**Mode B — self-track + mocap recovery.** Seed frame 0 from mocap, then `H_guess` = CELL's own
last estimate propagated by a **constant-velocity motion model**. Monitor the health signals
(§6); when tracking is lost (low inlier rate / large step for N frames), **re-seed `H_guess`
from mocap** for one frame and continue. Mocap-on-lost stands in for the global relocalizer
you'd use outside a mocap room; this demonstrates autonomous map-relative tracking with mocap
only as a safety net.

Make it a runtime switch (`--guess {mocap, selftrack}`), default `mocap`. The constant-velocity
model must extrapolate **only from confirmed frames**, hold position on a held/failed frame
(never dead-reckon off a failure — that is what causes runaway), and clamp the predicted
inter-frame step to a physical max.

## 8. COORDINATE FRAMES — get this right or everything is silently off

- **Map** `fused_clean_mocap.ply` is in the **mocap world frame** (aligned via the sim3).
- **Mocap poses** are world→body (or body→world — check the mocap driver's convention).
- CELL needs **world→CAMERA**: compose the mocap body pose with **`T_body_camera`** (invert as
  needed) to get `H_guess` (world→cam).
- Units are **metres** throughout (map, mocap, max_depth = 10). No scale conversion.
- The map, the poses and the predicted `H_est` share the same mocap world frame, so you can
  overlay `H_est` against mocap directly to measure live tracking error.

Validate the frames offline first: render the map depth from one logged mocap pose with the
recipe in §6 and overlay against the matching event frame — the depth edges should sit on the
event edges. If they don't, the frame composition (§8) or the half-res calib (§5) is wrong. Fix
that before going live.

## 9. Gotchas

- **Recompile the extensions** — don't reuse `.so` files built for a different
  torch/CUDA/cpython. (§3)
- **Half-res calib** — if `intrinsics.json` is full-res, divide by 2. (§5)
- **Depth channel** — feed `di[:, 1:2]` (partial_light completion), not ch0. (§5–§6)
- **No STC/Trail** live — train/test match requires the plain time surface. (§4)
- **CUDA init failures** — an unattended NVIDIA driver update mid-session can cause
  `CUDA Error 804` for new processes until a module reload/reboot; check `nvidia-smi` for a
  driver/library mismatch.
- **mathutils** must be importable (used by `data_preprocess`/`flow2pose` for RT construction).
- **Large files** — the checkpoint and map are not committed; download them from the hosting
  link (repo README / `drone_space/DATASET.md`).

---

## 10. Suggested bring-up order

1. Env + recompile extensions; `import` sanity check (§3).
2. Offline frame-composition validation: render map depth from a logged mocap pose, overlay on
   the matching event frame (§8). Must align before anything live.
3. Port the event representation to the event callback (§4); compare a live frame to a saved
   training frame of the same scene — distributions should match.
4. **Mode A live** (mocap-seeded) end-to-end through the ROS 1 IPC bridge; confirm `H_est`
   tracks mocap.
5. Add the motion model + health monitor + mocap recovery → **Mode B** (§7).
6. (Optional) edge-matching refinement (`tools/pose_refine`) for a small indoor accuracy bump,
   once the base loop is solid.
